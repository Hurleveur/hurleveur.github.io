Vault Map

Aug 03, 20264 min read

Map of the vault for AI agents. Read AGENTS first for rules, then this for where things live.

This file holds no counts and no file lists. Those drift, and for months they did — this map described seven folders that no longer existed and omitted six that did. Counts come from the embedded base below; folder notes are found by convention, not from an index kept here. If something can go stale, it does not belong in this prose.

Root files

  • AGENTS — rules and practices, read first
  • Vault Map — this file, where things live
  • Tags — what each workflow tag obliges an agent to do
  • README — setup notes for humans
  • help — the public site’s guide for visitors
  • woami — who the owner is
  • Obsidian Plugins — what’s installed and why
  • Focus point — the live personal todo list
  • log — append-only ledger of every change an agent makes

Projects (folder = project)

Purpose of each folder — the one thing a count can’t tell you:

  • Meaning/ — the largest project: purpose, creating, writing, songs, deep thoughts
  • Friends/ — a note per person met, plus the parsed WhatsApp exports under Texting/
  • Library/ — books read and the reading list; the public reading room
  • Work/ — work topics, guides, experience, thesis
  • Alignment/ — aligning current self with future self; life structure and health
  • Shared/ — the few outside things worth recommending: clippings, TV, thoughts
  • Daily Journal/ — daily notes
  • Travel/ — trips, and what being elsewhere taught me
  • Women/ — relationships
  • Data Mining/ — project: mining exported platform data into this vault with a local model
  • Website/ — planning and content for the public site
  • Excalidraw/ — drawings used to think above what fits in one head

System folders

  • Templates/ — one template per note type, plus Bases/ for the base definitions
  • Agent Log/ — one note per AI work session (format in Agent Log), plus log
  • Attachments/ — media; .obsidian/app.json sends attachments to a folder-relative Attachments/, so these exist per-folder too

Folder notes

Every folder’s note is Folder/Folder.md. The address is the convention, so this map keeps no list of them and no list of the missing ones — both went wrong in both directions when they were maintained by hand. To find folders lacking one:

Standing exceptions, so the command’s output can be read at a glance:

  • Website/ — its website.md predates the convention and is a raw idea dump; not renamed, because a case-only rename risks its links for a cosmetic gain
  • Attachments/, Templates/, Excalidraw/ and their subfolders (Templates/Bases/, Excalidraw/Scripts/, every nested */Attachments/) — mechanical folders, no reader, no note wanted

Everything the command prints should be on that list. Anything else is a real gap.

Folder notes that exist but are empty, and should get content on the next session in that folder: Daily Journal/ todo

Map maintenance

The base (Vault Map Base.base, Bases core plugin) carries everything countable: “Notes per folder” groups every note by file.folder; “By category” groups notes carrying categories:; “Work queue” lists every note tagged recurring, grouped by folder — an agent’s per-folder agenda.

Only two things here are manual, and neither can drift into a factual lie:

  • Folder purpose lines — a base can’t say why a folder exists. New project folder → add one line. The set of lines should match the base’s folder groups.
  • Root files list — short, rarely changes.

New workflow tag in AGENTS → add it to the Work queue view’s containsAny filter in the base.
